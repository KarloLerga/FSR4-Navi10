# FSR4-Navi10

An experimental Windows / DirectX 12 project targeting AMD Radeon RX 5700 XT (Navi10 / gfx1010), based on the FSR 4.0.2 source and model contract.

The requested endpoint is a deterministic standalone harness, a full FP16 Navi10 backend, an optional per-pass measured selector, and a separately named unsigned FSR API-compatible adapter. This checkout is still being implemented; `RESULTS.md` lists what has and has not been built or measured.

AMD currently documents FSR 4.0.2 for RX 9000 Series and above and distributes official integration as signed DLLs. This project is custom, unsigned, and not an AMD-supported game integration. It does not modify AMD drivers or signed binaries.

## Source and model inputs

Run `./scripts/fetch-upstreams.ps1` to fetch the pinned source and current API-reference SDK and create `third_party/LOCK.json`. The fetched checkouts and weights are ignored by Git. The project preserves their hashes and license provenance, and does not include them in its initial repository push.

## Build status

The initial DX12 adapter harness builds in Release and RelWithDebInfo. It lists the RX 5700 XT and reports D3D12, wave, and native 16-bit capabilities. `--run-fp16-probe` dispatches a small true-FP16 arithmetic shader on that GPU and verifies 64 results. DXC compiles the pinned upstream I8 shader entries for all 6 presets and 3 resolution tiers (252 pass outputs total). Run `cmake --build build/release --target compile_reference_i8_all` after fetching upstream; it writes DXIL and per-variant hash manifests under `build/release/reference/i8/`. The quicker `compile_reference_i8_native_1080` target builds just the native 1080p variant. `generate_native_1080_fp16_weight_pack` extracts/dequantizes 38 native/1080p INT8 weight tensors into FP16 and records their source and output hashes. That pack omits native-FP16 tensors, biases and runtime buffers and is not connected to a neural runtime. No FSR4 neural pass has been dispatched yet. The deterministic source inventory is generated by `python tools/model/extract_manifest.py`. Full FP16 model packing/execution, quality validation and FFX API adapter remain unimplemented. See `RESULTS.md` and `.agent/EXEC_PLAN.md` for current status.
